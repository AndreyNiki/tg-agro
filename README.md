# Telegram-бот расписания занятий

Бот поддерживает **произвольное число групп** одновременно: каждый
пользователь выбирает свою группу через `/start`, после чего получает
ежедневное сообщение с расписанием, уведомления об изменениях в течение
дня и умеет показывать расписание по запросу на любой день недели — с
картинкой, вырезанной прямо из официального PDF этой группы.

Как это устроено — см. `docs/superpowers/specs/2026-09-16-schedule-bot-design.md`.

## Возможности

- `/start` — выбор группы из списка (с пагинацией) или создание новой
  группы прямо в диалоге с ботом (бот сам находит PDF-ссылку группы по
  названию на странице-источнике и проверяет, что группа реально
  парсится из найденного PDF, прежде чем создать её).
- Ежедневное сообщение с расписанием на сегодня для каждой группы (время
  настраивается по группам).
- Периодическая проверка PDF-источника каждой группы на изменения (раз в
  час по умолчанию); при обнаружении диффа расписание обновляется и
  подписчикам этой группы сразу летит уведомление, что изменилось.
- Учёт типа учебной недели (Верхняя/Нижняя) — берётся с сайта института и
  переживает недоступность сайта (см. «Отказоустойчивость» ниже).
- Команда `/schedule` с кнопками дней недели — расписание на выбранный день
  + скриншот соответствующей полосы PDF.
- `/subscribe` / `/unsubscribe` — включить/выключить рассылку без потери
  привязки к группе.
- Админские команды для смены источника PDF конкретной группы, времени
  рассылки, интервала проверки, ручного форс-рефреша и рассылки
  произвольного сообщения всем пользователям бота.

## Требования

- Python 3.12+ (для локального запуска без Docker) или Docker + Docker Compose
  (рекомендуемый способ для продакшена).
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather).
- Свой Telegram `chat_id` для роли администратора (можно узнать, например,
  через [@userinfobot](https://t.me/userinfobot)).

## Быстрый старт (Docker, рекомендуется)

1. Скопируйте файл с переменными окружения и заполните его:

   ```bash
   cp .env.example .env
   ```

   Откройте `.env` и заполните как минимум:

   ```
   TELEGRAM_BOT_TOKEN=<токен от @BotFather>
   ADMIN_CHAT_ID=<ваш chat_id>
   ```

   Остальные переменные (`DAILY_SEND_TIME`, `CHECK_INTERVAL_MINUTES` и т.д.)
   уже заполнены разумными значениями по умолчанию — см. таблицу ниже, если
   нужно что-то поменять. Группы (название, ссылка на PDF, время рассылки
   и т.д.) в `.env` больше не настраиваются — они создаются прямо в
   диалоге с ботом, см. «Команды бота» ниже.

2. Соберите и запустите контейнер:

   ```bash
   docker compose up --build -d
   ```

   Контейнер выполняется от непривилегированного пользователя (uid 1000),
   не от root — если `./data` уже существует на хосте и принадлежит
   другому пользователю, дайте боту права на запись:
   `mkdir -p ./data/pdf_cache && chown -R 1000:1000 ./data`.

   При первом запуске бот:
   - создаст файл SQLite в `./data/schedule.db` (папка `./data` монтируется
     как volume, переживает пересборку и перезапуск контейнера);
   - засеет настройки значениями по умолчанию из `.env`;
   - если в базе есть данные от версии бота до многогруппового режима —
     смигрирует их в одну группу (см. «Обновление существующего
     развёртывания» ниже);
   - попробует получить тип недели с сайта института; если сайт недоступен,
     воспользуется резервной формулой (см. «Отказоустойчивость»);
   - начнёт ждать, пока пользователи создадут группы через `/start` — на
     fresh install групп нет, пока их никто не создаст через диалог
     создания группы.

3. Проверьте логи:

   ```bash
   docker compose logs -f
   ```

4. Откройте чат с ботом в Telegram и отправьте `/start`.

Остановить бота: `docker compose down` (данные в `./data` сохранятся).

## Локальный запуск без Docker

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполните TELEGRAM_BOT_TOKEN и ADMIN_CHAT_ID
mkdir -p data/pdf_cache
set -a; source .env; set +a
./.venv/bin/python main.py
```

`main.py` читает конфигурацию из переменных окружения процесса (через
`os.environ`), поэтому `.env` нужно явно подгрузить в shell (как выше) —
Docker-режим делает это сам через `env_file` в `docker-compose.yml`.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | — | Токен бота от @BotFather |
| `ADMIN_CHAT_ID` | да | — | Telegram chat_id администратора — только этот chat может выполнять админские команды |
| `DB_PATH` | нет | `./data/schedule.db` | Путь к файлу SQLite |
| `PDF_CACHE_DIR` | нет | `./data/pdf_cache` | Куда сохранять кэш-копии применённых версий PDF (нужны для рендера скриншотов дня) |
| `WEEKTYPE_URL` | нет | `https://www.vavilovsar.ru/ucheba/raspisanie-zanyatii` | Страница, откуда вытаскивается формула чётности недели |
| `DAILY_SEND_TIME` | нет | `09:00` | Время ежедневной рассылки **по умолчанию для новых групп**, формат `HH:MM`, в таймзоне `TIMEZONE` (у каждой группы своё значение можно поменять через `/set_send_time`) |
| `CHECK_INTERVAL_MINUTES` | нет | `60` | Как часто по умолчанию проверять PDF новой группы на изменения (в минутах); тоже настраивается по группам через `/set_check_interval` |
| `TIMEZONE` | нет | `Europe/Moscow` | Таймзона планировщика по умолчанию для новых групп |
| `LEGACY_GROUP_SOURCE_PAGE_URL` | только при обновлении | — | См. «Обновление существующего развёртывания» ниже — не нужна для свежей установки |

Группы (название, ссылка на PDF, время рассылки, интервал проверки,
таймзона) хранятся в таблице `groups` в SQLite, создаются через диалог
создания группы в `/start` и настраиваются на лету админскими командами
(см. ниже) — без пересборки/рестарта контейнера.

## Команды бота

### Пользовательские (доступны всем)

| Команда | Что делает |
|---|---|
| `/start` | Если группа ещё не выбрана — показывает список групп (с пагинацией) и кнопку «➕ Создать группу»; выбор группы в списке подписывает на её рассылку. Если группа уже выбрана — показывает текущую группу и статус подписки |
| `/subscribe` | Включить рассылку расписания (группа остаётся той же, что выбрана через `/start`) |
| `/unsubscribe` | Отключить рассылку; группа остаётся закреплённой, `/schedule` продолжает работать |
| `/schedule` | Показать кнопки дней недели (Пн–Сб) для своей группы; по нажатию — текст расписания на выбранный день (для ближайшей даты этого дня недели, с учётом типа недели) + скриншот соответствующей полосы PDF, если он доступен |
| `/help` | Список доступных команд (админу — ещё и список админских) |

**Создание новой группы.** Если нужной группы нет в списке `/start`,
кнопка «➕ Создать группу» запускает короткий диалог: бот спрашивает
точное название группы (как оно выглядит в PDF-таблице расписания), затем
ссылку на страницу со списком ссылок на PDF всех групп. Бот сам находит
нужную PDF-ссылку по названию группы, скачивает PDF и проверяет, что
группа реально существует как колонка в таблице, прежде чем создать
группу — это исключает создание «мёртвой» группы, которая никогда не
сможет синхронизироваться. `/cancel` в любой момент диалога его отменяет.

### Административные (только `ADMIN_CHAT_ID`)

Любая из этих команд, вызванная не-админом, отвечает «Недостаточно прав.»
и ничего не меняет. Команды, оперирующие конкретной группой, принимают
`group_id` первым аргументом (его можно увидеть, например, в сообщении
`/refresh`/`/set_*` или в логах).

| Команда | Аргументы | Что делает |
|---|---|---|
| `/set_pdf_source <group_id> <url_или_путь>` | id группы, URL или локальный путь | Меняет источник PDF этой группы немедленно, без рестарта |
| `/set_send_time <group_id> <HH:MM>` | id группы, время, например `07:30` | Меняет время ежедневной рассылки этой группы и сразу переустанавливает её джобу в планировщике |
| `/set_check_interval <group_id> <минуты>` | id группы, положительное целое, например `30` | Меняет интервал проверки PDF этой группы на изменения и сразу переустанавливает джобу |
| `/refresh <group_id>` | id группы | Немедленно запускает проверку-и-применение diff для этой группы (та же логика, что в фоновых джобах), не дожидаясь расписания. Отвечает: «Изменений нет.» / «Расписание загружено впервые.» / «Расписание обновлено и разослано подписчикам.» |
| `/alert <текст>` | произвольный текст | Немедленно рассылает текст всем пользователям бота во всех группах (например, если админ вручную заметил ошибку в расписании до автопроверки) |

`/set_send_time` и `/set_check_interval` валидируют аргумент до записи в
базу — некорректный формат (`9h30`, `abc`) отклоняется с понятным
сообщением, ничего не сохраняется и планировщик не трогается.

## Планировщик

Для **каждой группы** независимо заводится своя пара фоновых задач
(APScheduler):

- **Ежечасная проверка** (своя для группы, по умолчанию
  `CHECK_INTERVAL_MINUTES` минут) — парсит PDF группы, сравнивает с
  активной версией; если есть отличия — сразу применяет и рассылает
  подписчикам этой группы сообщение «Расписание изменилось: ...».
- **Ежедневная рассылка** (своя для группы, по умолчанию
  `DAILY_SEND_TIME`) — сначала делает ту же проверку-и-применение, затем
  в любом случае отправляет подписчикам этой группы расписание на
  сегодня (текст + скриншот дня, если есть).

Плюс одна общая на весь бот задача:

- **Еженедельное обновление формулы недели** (по понедельникам в 06:00,
  не настраивается) — перечитывает `WEEKTYPE_URL` и обновляет тип недели
  для всех групп сразу, на случай если институт поменяет формулу.

## Отказоустойчивость

- Если сайт с типом недели недоступен или поменял разметку при старте —
  бот использует последнюю успешно сохранённую формулу из настроек, а если
  и её ещё нет — встроенный резервный вариант (5 января = опорная дата).
  Бот **не падает** при старте из-за недоступности сайта.
- Если в PDF-кэше не оказалось нужного файла (случайно удалили том) — бот
  присылает текст расписания без скриншота и пишет предупреждение в лог,
  не прерывая отправку.
- Сбой у одного подписчика (например, он заблокировал бота) не мешает
  разослать сообщение остальным — ни в ежедневной рассылке, ни в
  `/alert`, ни при уведомлении об изменении расписания.
- PDF при каждой синхронизации скачивается один раз и парсится из той же
  копии, что кэшируется — данные и картинка гарантированно согласованы.
  Устаревшие кэш-файлы предыдущих версий удаляются автоматически.

## Обновление существующего развёртывания

Если вы запускаете эту версию бота поверх базы данных, созданной
версией *до* многогруппового режима (одна глобальная группа, настройки
`GROUP_NAME`/`PDF_SOURCE` в `.env`), при первом старте бот автоматически
смигрирует эти данные в одну группу в новой схеме (таблицы `groups` и
`members`) — существующие подписчики автоматически окажутся привязаны к
этой группе и продолжат получать рассылку без каких-либо действий с их
стороны.

Для этого обязательно нужно установить переменную
`LEGACY_GROUP_SOURCE_PAGE_URL` — страницу со списком ссылок на PDF всех
групп (ту же, что бот сейчас запрашивает в диалоге создания группы). Она
нужна на случай, если ссылка на PDF успела протухнуть к моменту
обновления — миграция должна уметь её переоткрыть. Без этой переменной
(если в базе обнаружены данные для миграции) бот откажется запускаться с
понятной ошибкой.

На свежей установке (пустая база) эта переменная не нужна — миграция
определяет, что мигрировать нечего, и ничего не делает.

## Структура проекта

```
main.py                    — точка входа: сборка Application, регистрация хендлеров, планировщик
schedule_bot/
  config.py                — загрузка конфигурации из переменных окружения
  storage.py                — SQLite: настройки, подписчики, версии расписания
  weektype.py                — парсинг формулы типа недели + её персистентность
  pdf_parser.py              — разбор PDF-таблицы расписания (геометрия, объединённые ячейки, верхняя/нижняя неделя)
  diff.py                     — сравнение двух версий расписания
  screenshot.py                — вырезка полосы дня из PDF в PNG (PyMuPDF)
  formatting.py                 — текст сообщения с расписанием на день
  sync.py                        — оркестрация «скачать → сравнить → применить → уведомить»
  scheduler.py                    — джобы APScheduler (своя пара на группу + общая еженедельная)
  bot.py                            — хендлеры команд Telegram (schedule, admin-команды по группам)
  group_commands.py                  — /start, /subscribe, /unsubscribe, диалог создания группы
  group_links.py                       — поиск PDF-ссылки группы на странице-источнике
tests/                              — тесты (pytest), включая реальный PDF-фикстюр
docs/superpowers/specs/             — дизайн-спека
docs/superpowers/plans/             — план реализации (TDD, по задачам)
```
