# Telegram-бот расписания занятий

Бот поддерживает **произвольное число институтов и групп** одновременно:
администратор добавляет институт с одной ссылкой на главную страницу
каталога, бот сам находит на ней страницы форм обучения (очная/очно-
заочная/заочная — сколько из трёх есть), сканирует каждую на PDF-ссылки
и создаёт группы, а
пользователь через `/start` выбирает институт → свою группу. Дальше он
получает ежедневное сообщение с расписанием, уведомления об изменениях в
течение дня и умеет показывать расписание на любой день недели — с
картинкой, вырезанной прямо из официального PDF (колонка времени +
колонка своей группы).

Как это устроено:
- `docs/superpowers/specs/2026-09-16-schedule-bot-design.md` — базовая архитектура;
- `docs/superpowers/specs/2026-10-09-institutes-and-shared-schedules-design.md`
  — актуальная модель «институт → ссылка каталога → группы», дедупликация
  скачивания/парсинга общих PDF и кроп одной колонки на скриншоте.

## Возможности

- `/start` — выбор института из списка (с пагинацией), затем группы этого
  института. Пользователи группы не создают: группы появляются из
  сканирования каталога института.
- Группа из каталога считается **непроверенной** (`is_verified = 0`), пока
  на неё не подпишется первый пользователь: в этот момент бот скачивает
  PDF ссылки, проверяет, что колонка с таким названием реально есть в
  шапке таблицы, и сразу же делает первую сверку, чтобы `/schedule`
  работал немедленно. Если колонки нет — группа помечается
  `is_verified = -1`, скрывается из пикеров, администратору уходит алерт.
- Ежедневное сообщение с расписанием на сегодня (время рассылки
  настраивается **по институту**).
- Периодическая сверка PDF каждой ссылки каталога на изменения (раз в час
  по умолчанию, интервал задаётся по институту); при обнаружении диффа
  расписание обновляется и подписчикам соответствующих групп сразу летит
  уведомление.
- Один PDF-файл, покрывающий несколько групп, скачивается и парсится
  **один раз** за цикл сверки, независимо от числа подписанных на него
  групп. Сверка вообще не делается для ссылок без закреплённых
  пользователей и для устаревших (`is_stale`) ссылок.
- Фоновое пересканирование каталога института (по умолчанию раз в неделю,
  `CATALOG_REFRESH_INTERVAL_MINUTES`): новые ссылки/группы появляются
  сами, исчезнувшие ссылки помечаются `is_stale` (а не удаляются) с
  одним алертом администратору, если у них были подписчики.
- Учёт типа учебной недели (Верхняя/Нижняя) — берётся с сайта института и
  переживает недоступность сайта (см. «Отказоустойчивость» ниже).
- Команда `/schedule` с кнопками дней недели — расписание на выбранный день
  + скриншот (шапка + колонка времени + колонка группы).
- `/subscribe` / `/unsubscribe` — включить/выключить рассылку без потери
  привязки к группе.
- `/change_group` — заявка на переход в другую группу (решает админ или
  староста целевой группы).
- Админские команды для управления институтами (каталог, интервалы, время
  рассылки, пересканирование, диагностика ссылок), ручного форс-рефреша
  и рассылки произвольного сообщения всем пользователям бота.

## Требования

- Python 3.12+ (для локального запуска без Docker) или Docker + Docker Compose
  (рекомендуемый способ для продакшена).
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather).
- Свой Telegram `chat_id` для роли администратора (можно узнать, например,
  через [@userinfobot](https://t.me/userinfobot)).

## Быстрый старт (Docker, рекомендуется)

1. Скопируйте файл с переменными окружения и заполните его:

   ```bash
   cp .env.example .env
   ```

   Откройте `.env` и заполните как минимум:

   ```
   TELEGRAM_BOT_TOKEN=<токен от @BotFather>
   ADMIN_CHAT_ID=<ваш chat_id>
   ```

   Остальные переменные (`DAILY_SEND_TIME`, `CHECK_INTERVAL_MINUTES`,
   `CATALOG_REFRESH_INTERVAL_MINUTES` и т.д.) уже заполнены разумными
   значениями по умолчанию — см. таблицу ниже. Это именно **значения по
   умолчанию для новых институтов**: институты и их настройки живут в
   SQLite и меняются на лету админскими командами.

2. Соберите и запустите контейнер:

   ```bash
   docker compose up --build -d
   ```

   Контейнер выполняется от непривилегированного пользователя (uid 1000),
   не от root — если `./data` уже существует на хосте и принадлежит
   другому пользователю, дайте боту права на запись:
   `mkdir -p ./data/pdf_cache && chown -R 1000:1000 ./data`.

   При первом запуске бот:
   - создаст файл SQLite в `./data/schedule.db` (папка `./data` монтируется
     как volume, переживает пересборку и перезапуск контейнера);
   - засеет настройки значениями по умолчанию из `.env`;
   - попробует получить тип недели с сайта института; если сайт недоступен,
     воспользуется резервной формулой (см. «Отказоустойчивость»);
   - начнёт ждать, пока администратор добавит первый институт
     (`/add_institute`) — на fresh install институтов и групп нет.

3. Проверьте логи:

   ```bash
   docker compose logs -f
   ```

4. Откройте чат с ботом в Telegram, отправьте `/add_institute <название>
   <url_каталога>` от админского chat_id, затем `/start` — в пикере
   появятся институт и найденные в каталоге группы.

Остановить бота: `docker compose down` (данные в `./data` сохранятся).

## Локальный запуск без Docker

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполните TELEGRAM_BOT_TOKEN и ADMIN_CHAT_ID
mkdir -p data/pdf_cache
set -a; source .env; set +a
./.venv/bin/python main.py
```

`main.py` читает конфигурацию из переменных окружения процесса (через
`os.environ`), поэтому `.env` нужно явно подгрузить в shell (как выше) —
Docker-режим делает это сам через `env_file` в `docker-compose.yml`.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | — | Токен бота от @BotFather |
| `ADMIN_CHAT_ID` | да | — | Telegram chat_id администратора — только этот chat может выполнять админские команды |
| `DB_PATH` | нет | `./data/schedule.db` | Путь к файлу SQLite |
| `PDF_CACHE_DIR` | нет | `./data/pdf_cache` | Куда сохранять кэш-копии применённых версий PDF (нужны для рендера скриншотов дня) |
| `WEEKTYPE_URL` | нет | `https://www.vavilovsar.ru/ucheba/raspisanie-zanyatii` | Страница, откуда вытаскивается формула чётности недели |
| `DAILY_SEND_TIME` | нет | `09:00` | Время ежедневной рассылки **по умолчанию для новых институтов**, формат `HH:MM`, в таймзоне `TIMEZONE` (у института значение меняется через `/set_institute_send_time`) |
| `CHECK_INTERVAL_MINUTES` | нет | `60` | Как часто по умолчанию сверять PDF ссылок нового института (в минутах); меняется через `/set_institute_check_interval` |
| `CATALOG_REFRESH_INTERVAL_MINUTES` | нет | `10080` (неделя) | Как часто по умолчанию пересканировать главную страницу каталога института (и найденные на ней страницы форм обучения); меняется через `/set_institute_catalog_interval` |
| `LEGACY_MIGRATION_INSTITUT`, `LEGACY_MIGRATION_INSTITUT_NAME`, `LEGACY_MIGRATION_GROUP_NAME` | нет | — | Одноразовая миграция всех существующих `members` на одну группу (см. `.env.example`); требуются все три сразу, выполняется не более одного раза |
| `TIMEZONE` | нет | `Europe/Moscow` | Таймзона планировщика по умолчанию для новых институтов |

Институты (название, URL каталога, время рассылки, интервал сверки,
интервал пересканирования каталога, таймзона), их ссылки
(`institute_links`) и группы хранятся в SQLite и настраиваются на лету
админскими командами — без пересборки/рестарта контейнера. Группы и
ссылки создаются **только** сканированием каталога.

## Команды бота

### Пользовательские (доступны всем)

| Команда | Что делает |
|---|---|
| `/start` | Если группа ещё не выбрана — показывает список институтов (с пагинацией), затем группы выбранного института; выбор группы подписывает на её рассылку (с проверкой группы по PDF и немедленной первой сверкой, если группа ещё не проверялась). Если группа уже выбрана — показывает текущую группу и статус подписки |
| `/subscribe` | Включить рассылку расписания (группа остаётся той же) |
| `/unsubscribe` | Отключить рассылку; группа остаётся закреплённой, `/schedule` продолжает работать |
| `/schedule` | Показать кнопки дней недели (Пн–Сб) для своей группы; по нажатию — текст расписания на выбранный день + скриншот (шапка + колонка времени + колонка группы), если он доступен |
| `/change_group` | Заявка на переход в другую группу (одобряет админ или староста целевой группы) |
| `/classmates`, `/starosta`, `/votes`, `/report`, `/faq` | Одногруппники, выборы/привилегии старосты, сообщение о проблеме, справка |
| `/help` | Список доступных команд (админу — ещё и список админских) |

Создавать группы и указывать ссылки на PDF пользователь не может: всё
берётся из каталога института. Если нужной группы нет в списке — значит
её не нашлось в каталоге (или её название не прошло проверку по реальному
PDF); это диагностируется админской командой `/institute_links`.

### Административные (только `ADMIN_CHAT_ID`)

Любая из этих команд, вызванная не-админом, отвечает «Недостаточно прав.»
и ничего не меняет.

| Команда | Аргументы | Что делает |
|---|---|---|
| `/add_institute <название> <url_каталога>` | название, URL главной страницы каталога (НЕ страницы конкретной формы обучения — бот сам найдёт на ней ссылки на очную/очно-заочную/заочную формы и просканирует их) | Создаёт институт с дефолтами из `.env`, сразу сканирует каталог и регистрирует job'ы. В ответе честно сообщает, сколько ссылок найдено (в том числе «ссылок не найдено») |
| `/set_institute_catalog_url <id> <url>` | id института, URL главной страницы каталога | Меняет страницу-каталог института |
| `/set_institute_check_interval <id> <минуты>` | id института, положительное целое | Меняет интервал сверки PDF и переустанавливает job'ы всех ссылок института |
| `/set_institute_send_time <id> <HH:MM>` | id института, время | Меняет время ежедневной рассылки и переустанавливает job'ы всех ссылок института |
| `/set_institute_catalog_interval <id> <минуты>` | id института, положительное целое | Меняет периодичность фонового пересканирования каталога |
| `/refresh_institute_links <id>` | id института | Немедленно пересканирует каталог: создаёт/обновляет ссылки и группы, помечает исчезнувшие ссылки `is_stale`, регистрирует job'ы для новых ссылок |
| `/institute_links <id>` | id института | Диагностика: подписи ссылок каталога, число групп у каждой (включая 0) и пометка `[stale]` |
| `/refresh <group_id>` | id группы | Немедленно запускает сверку **ссылки** этой группы (та же единица работы и тот же lock, что у планового job'а), не дожидаясь расписания |
| `/alert <текст>` | произвольный текст | Немедленно рассылает текст всем пользователям бота во всех группах |
| `/notify`, `/close_group`, `/open_group`, `/set_starosta`, `/remove_starosta`, `/requests` | см. `/help` | Операции по конкретной группе (`group_id` первым аргументом) |

Групповые команды `/set_pdf_source`, `/set_send_time`,
`/set_check_interval` **удалены**: соответствующих атрибутов у группы
больше нет, их место заняли настройки института
(`/set_institute_*`). То же касается меню: подменю «Источник PDF»/«Время
рассылки»/«Интервал проверки» заменено разделом «🏫 Институты».

`/set_institute_send_time` и `/set_institute_*_interval` валидируют
аргумент до записи в базу — некорректный формат (`9h30`, `abc`)
отклоняется с понятным сообщением, ничего не сохраняется и планировщик не
трогается.

## Планировщик

Задачи (APScheduler) заводятся **на уровне ссылки каталога**
(`institute_links`), а не группы и не института — так число job'ов
порядка числа ссылок, и один job не «расползается» на десятки
последовательных скачиваний:

- `link_check_<link_id>` — интервальная сверка (интервал берётся у
  института, по умолчанию `CHECK_INTERVAL_MINUTES`): скачивает PDF ссылки
  один раз, парсит один раз, применяет результат к каждой её группе с
  подписчиками и рассылает «Расписание изменилось…» затронутым группам.
  Ссылки без закреплённых пользователей и `is_stale`-ссылки выходят сразу,
  без сетевых запросов.
- `link_daily_send_<link_id>` — ежедневная рассылка в `send_time`
  института (CronTrigger в таймзоне института): сначала та же сверка,
  затем всем подписчикам групп этой ссылки — расписание на сегодня
  (текст + скриншот дня, если есть).
- `institute_catalog_refresh_<institute_id>` — фоновое пересканирование
  каталога института (фетч главной страницы + фетч каждой найденной на
  ней страницы формы обучения, без скачивания PDF; если одна из страниц
  форм временно недоступна — её ссылки просто отсутствуют в этом скане,
  остальные формы сканируются как обычно).
  После успешного скана сразу регистрирует job'ы для найденных новых
  ссылок.

Плюс одна общая на весь бот задача:

- **Еженедельное обновление формулы недели** (по понедельникам в 06:00,
  не настраивается) — перечитывает `WEEKTYPE_URL` и обновляет тип недели
  для всех групп сразу, на случай если институт поменяет формулу.

## Отказоустойчивость

- Если сайт с типом недели недоступен или поменял разметку при старте —
  бот использует последнюю успешно сохранённую формулу из настроек, а если
  и её ещё нет — встроенный резервный вариант (5 января = опорная дата).
  Бот **не падает** при старте из-за недоступности сайта.
- Каталог, вернувший 0 PDF-ссылок (битая страница, редизайн сайта), **не
  обнуляет** привязки: БД не трогается, администратору уходит алерт.
- Ссылка, исчезнувшая из каталога, помечается `is_stale = 1`, а не
  удаляется: группы остаются, `/schedule` продолжает отдавать последнюю
  успешно засинканную версию, администратор получает **один** алерт с
  числом затронутых подписчиков. По устаревшим ссылкам бот больше не
  делает сетевых запросов.
- 404 на PDF-ссылке триггерит пересканирование каталога не чаще одного
  раза за интервал сверки института (общий на все ссылки и на ручной
  `/refresh`), после чего адрес ссылки перечитывается из БД и попытка
  повторяется.
- Если в PDF-кэше не оказалось нужного файла (случайно удалили том) — бот
  присылает текст расписания без скриншота и пишет предупреждение в лог,
  не прерывая отправку. На путях рассылки администратору уходит **один**
  алерт за прогон, а не на каждого подписчика.
- Сбой у одного подписчика (например, он заблокировал бота) не мешает
  разослать сообщение остальным — ни в ежедневной рассылке, ни в
  `/alert`, ни при уведомлении об изменении расписания.
- PDF при каждой синхронизации скачивается один раз и парсится из той же
  копии, что кэшируется — данные и картинка гарантированно согласованы.
  Устаревшие кэш-файлы предыдущих версий удаляются автоматически.
- Все блокирующие операции (фетч каталога, скачивание и разбор PDF)
  выполняются в `asyncio.to_thread` — один медленный сайт не
  останавливает обработку апдейтов остальных пользователей.

## Структура проекта

```
main.py                    — точка входа: сборка Application, регистрация хендлеров, планировщик
schedule_bot/
  config.py                — загрузка конфигурации из переменных окружения
  storage.py                — SQLite: настройки, институты, ссылки каталога, группы, подписчики, версии расписания
  weektype.py                — парсинг формулы типа недели + её персистентность
  pdf_parser.py              — разбор PDF-таблицы расписания (геометрия, объединённые ячейки, верхняя/нижняя неделя)
  diff.py                     — сравнение двух версий расписания
  screenshot.py                — вырезка шапки + колонки времени + колонки группы из PDF в PNG (PyMuPDF)
  formatting.py                 — текст сообщения с расписанием на день
  sync.py                        — сверка на уровне ссылки: «скачать и распарсить один раз → применить каждой группе → уведомить»
  scheduler.py                    — джобы APScheduler (пара на ссылку + каталог на институт + общая еженедельная)
```
