# Инлайн-меню — дизайн

Дата: 2026-10-08

Под-проект 5 из 5 (мультигрупповость → старосты → соцслой →
привилегии старосты → **UI-меню**). Зависит от всех предыдущих
под-проектов — это надстройка-навигация над уже существующими
командами, не новая бизнес-логика. Текстовые команды (`/schedule`,
`/notify`, `/set_send_time` и т.д.) продолжают работать напрямую и
независимо от меню; `/help` не меняется.

## Точка входа

- Новая команда `/menu` — показывает корень дерева.
- Ответ `/start` (под-проект 1, `group_commands.start_command`) при уже
  закреплённой группе получает дополнительную кнопку «📋 Меню»,
  открывающую то же дерево — не нужно отдельно вспоминать `/menu`.

## Структура дерева

Навигация — `callback_data` вида `menu:<раздел>:<действие>`,
`menu:back:<уровень>` для возврата; переключение экрана делается через
`query.message.edit_text(...)`/`edit_reply_markup(...)`, не новым
сообщением (как при пагинации групп в под-проекте 1).

Корень (видимость зависит от роли вызывающего в его группе,
пересчитывается на каждый показ — не кэшируется):

- **📅 Расписание** (есть у любого с закреплённой группой):
  `/schedule`-пикер дня, переключатель «Подписаться/Отписаться»
  (подпись зависит от текущего `members.subscribed`).
- **👥 Группа** (есть у любого с закреплённой группой): «📋
  Одногруппники» (`/classmates`), «🔄 Сменить группу» (`/change_group`
  флоу из под-проекта 2, включая подтверждение), «🗳 Открытые
  голосования» (`/votes` из под-проекта 2 — пустой список тоже
  показывается, не скрывается).
- **👑 Староста** (есть у любого с закреплённой группой; содержимое
  зависит от состояния):
  - `starosta_chat_id IS NULL` → кнопка «🙋 Я староста» (если группа
    проходит проверку минимального размера из под-проекта 2; иначе —
    текст с причиной вместо кнопки, без её отображения).
  - `starosta_chat_id` назначен и это не вызывающий → кнопка «🔁
    Староста изменился» (если кулдаун прошёл; иначе — текст с датой,
    когда можно повторить, без кнопки).
  - вызывающий сам староста → привилегии из под-проекта 4: «❌
    Исключить участника» (список с кнопками исключения), «🔒 Закрыть
    группу» / «🔓 Открыть группу» (подпись и действие зависят от
    текущего `groups.is_closed`), «📢 Оповестить группу» (запрашивает
    текст), «📥 Заявки» (`/requests` без аргумента — своя группа).
- **⚙️ Админ** (только `is_admin()`): «📢 Объявление всем» (глобальный
  `/alert`, запрашивает текст), «🔧 Настройки группы» (пикер группы →
  подменю `set_pdf_source`/`set_send_time`/`set_check_interval`/
  `refresh`), «👑 Старосты» (пикер группы → запрос `chat_id` →
  `set_starosta`/`remove_starosta`), «🔒 Открытость группы» (пикер
  группы → переключатель `is_closed`), «📥 Заявки» (пикер группы →
  `/requests <group_id>`).

Каждый уровень — кнопка «◀️ Назад».

## Выполнение пунктов без дублирования логики

Два вида пунктов:

**Беспараметрические** — кнопка сразу вызывает ту же async-функцию,
что и соответствующая команда (без парсинга `context.args`); там, где
команде обычно нужен `group_id` явным аргументом, меню уже знает его
из роли вызывающего (своя группа как старосты, или группа, выбранная
на предыдущем шаге пикера). Сюда попадают: расписание на день,
одногруппники, подписка/отписка, «я староста»/«староста изменился» (у
них и так свой пикер кандидатов дальше), переключатель
закрыть/открыть свою группу.

**С текстовым параметром** — `set_pdf_source`, `set_send_time`,
`set_check_interval`, `set_starosta`/`remove_starosta`, глобальный
`alert`, `notify`. Чтобы не продублировать валидацию и запись в БД,
каждая такая команда из под-проектов 1/2/4 получает отдельную
**core-функцию без `Update`/`context.args`**, например:

```python
def _apply_set_send_time(conn, group: GroupRow, value: str) -> str:
    """Validates `value`, updates storage, returns the reply text.
    Called by both set_send_time_command (parses context.args) and the
    menu's generic pending-action follow-up (parses a free-text reply)."""
```

Существующий текстовый хендлер (`set_send_time_command` и т.п.) после
этого рефакторинга сводится к: проверке прав/парсингу `context.args` →
вызову `_apply_set_send_time(...)` → `reply_text(...)`. Нажатие пункта
в меню сохраняет `context.user_data["pending_menu_action"] =
{"action": "set_send_time", "group_id": ...}` и просит «Отправьте новое
значение»; один общий `MessageHandler` (зарегистрированный в `main.py`
после всех `ConversationHandler`, чтобы не перехватывать их собственные
текстовые шаги) проверяет `pending_menu_action` в `user_data` и вызывает
соответствующую core-функцию с введённым текстом, очищая
`pending_menu_action` после обработки (успешной или нет — одна попытка
на один заход в меню, повторный вызов пункта меню создаёт новый
`pending_menu_action`).

Действиям, которым нужен и выбор группы, и значение (большинство
admin-пунктов) — сначала пикер групп, который записывает `group_id` в
тот же `pending_menu_action` до того, как запросить значение.

## Видимость и совместимость

- Раздел «👑 Староста» вычисляется заново при каждом показе меню — ни
  состояние роли, ни кулдаун не кэшируются между открытиями.
- Раздел «⚙️ Админ» — обычная проверка `is_admin()`.
- `/help` не меняется.
- Любая ошибка внутри core-функции (невалидное значение, группа не
  найдена и т.п.) возвращает тот же текст ошибки, что и при вызове
  текстовой командой — единый источник сообщений, только путь вызова
  разный.

## Тестирование

- Для каждой извлечённой core-функции (`_apply_set_send_time` и
  аналоги) — юнит-тесты валидации, идентичные существующим тестам
  команд (переносятся на core-функцию, тонкий хендлер проверяется
  отдельно только на «парсит args → зовёт core → шлёт ответ core»).
- Построение корня меню — тест на три комбинации роли (обычный
  участник / староста / админ) → ожидаемый набор видимых кнопок.
- Раздел «Староста» — тест на три состояния (`starosta_chat_id` пуст /
  назначен не на вызывающего / назначен на вызывающего) → ожидаемая
  кнопка или текст-причина.
- `pending_menu_action` — тест, что общий `MessageHandler` вызывает
  правильную core-функцию с правильным `group_id`, и что он не
  перехватывает сообщения, когда `pending_menu_action` не установлен
  (обычный текст не должен попадать в этот хендлер).
- Навигация «Назад» — тест, что возврат показывает именно предыдущий
  уровень, а не корень.

## Вне охвата этого под-проекта

- Любая новая бизнес-логика — это чисто навигационная надстройка,
  core-функции только извлекаются из уже спроектированных команд, не
  получают новых возможностей.
