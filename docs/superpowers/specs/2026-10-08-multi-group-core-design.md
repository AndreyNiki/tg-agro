# Ядро мультигрупповости — дизайн

Дата: 2026-10-08

Под-проект 1 из 5 в рамках крупной доработки (мультигрупповость → старосты →
соцслой → привилегии старосты → UI-меню). Этот документ покрывает только
переход от «одна группа на весь бот» к «много групп, каждый пользователь
закреплён за одной из них», плюс попутное исправление бага со сменой
ссылки на PDF. Роль старосты, голосования, соцслой, закрытые группы,
`/notify` и редизайн меню — отдельные под-проекты, не входят в этот спек.

## Текущее состояние (до изменений)

Один инстанс бота = одна группа. Источник правды — таблица `settings`
(key-value): `pdf_source`, `group_name`, `weektype_url`,
`daily_send_time`, `check_interval_minutes`, `timezone`. Подписчики —
`subscribers(chat_id PRIMARY KEY, group_name, joined_at)`, один chat_id
может быть подписан только на одну (на деле — единственную существующую)
группу. `admin_chat_id` — одиночный `int`, сравнение по равенству
(`is_admin()` в `bot.py`). Один hourly- и один daily-job в APScheduler на
весь бот. Известный существующий баг: `bot_data["group_name"]` — снэпшот
на момент старта процесса, не обновляется после `/set_group` (описан в
CLAUDE.md как принятое ограничение — в этом спеке устраняется, см.
«Выбор группы»).

Известный новый баг, мотивирующий часть этой доработки: ссылка на PDF
меняется институтом при обновлении расписания (имя файла меняется), и
бот не умеет сам находить новую ссылку — просто начинает получать 404.

## Модель данных

### Таблица `groups`

```
groups(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  source_page_url TEXT NOT NULL,
  pdf_source_url TEXT NOT NULL,
  send_time TEXT NOT NULL,
  check_interval_minutes INTEGER NOT NULL,
  timezone TEXT NOT NULL,
  last_sync_failed_at TEXT,
  created_at TEXT NOT NULL
)
```

- `source_page_url` — страница института со списком ссылок на PDF всех
  групп (та же, что используется для 404-реканекта, см. ниже).
- `pdf_source_url` — резолвленная на момент создания/последнего успешного
  синка ссылка на конкретный PDF этой группы; может быть переписана при
  404-реканекте.
- `send_time`/`check_interval_minutes`/`timezone` — бывшие глобальные
  настройки из `settings`, теперь per-group; новые группы получают
  значения по умолчанию из `config` (как раньше задавались глобально),
  меняет их только глобальный админ.
- `last_sync_failed_at` — бывший глобальный `settings.last_sync_failed_at`,
  теперь per-group (сбой синка одной группы не должен влиять на
  предупреждение о "устаревшем расписании" у другой).
- `weektype_url` и формула типа недели **остаются глобальными**
  (`settings.weektype_url`, `weekly_weektype_refresh_job`,
  `WeekFormulaHolder` без изменений) — это одна и та же страница
  института для всех групп, вводить per-group-копию формулы ради
  гипотетического различия, которого никто не просил, было бы
  избыточным усложнением (YAGNI).

### Таблица `members` (заменяет `subscribers`)

```
members(
  chat_id INTEGER PRIMARY KEY,
  group_id INTEGER NOT NULL REFERENCES groups(id),
  telegram_username TEXT,
  display_name TEXT,
  subscribed BOOLEAN NOT NULL DEFAULT 1,
  joined_at TEXT NOT NULL
)
```

- PK на `chat_id` сохраняет инвариант «один пользователь — одна
  закреплённая группа одновременно» (смена группы — предмет под-проекта
  2, не входит сюда).
- `subscribed=false` гасит рассылку, но не отвязывает от группы —
  `/schedule` и прочие группо-зависимые команды продолжают работать.
- `telegram_username`/`display_name` — задел под соцслой (под-проект 3),
  заполняется уже в этом под-проекте, т.к. данные бесплатно доступны в
  любом `Update` и теряются, если не собирать их сразу.

### Таблица `schedule_versions`

Без изменений в схеме — `group_name TEXT` заменяется на `group_id
INTEGER REFERENCES groups(id)` (переименование колонки + тип), остальная
логика (`active`/`superseded`, diff против активной версии той же
группы) не меняется.

### Миграция существующих данных

Выполняется один раз при старте, если `groups` пуста:

1. Если в `settings` есть старые `group_name`/`pdf_source`/... — создать
   из них единственную строку `groups` (с `source_page_url`, равным
   текущему `weektype_url`-соседу... на деле `source_page_url` для старой
   группы неизвестен — см. «Открытый вопрос» ниже). Иначе создать группу
   из `config`-дефолтов.
2. Перенести все строки `subscribers` → `members` на `group_id` этой
   первой группы, `subscribed=true`.
3. Для каждого перенесённого `chat_id` разово вызвать `bot.get_chat(chat_id)`,
   чтобы backfill-нуть `telegram_username`/`display_name`. Ошибка вызова
   (юзер заблокировал бота, chat not found) — не фейлит миграцию, поле
   остаётся `NULL` и самовосстановится при следующем взаимодействии.
4. Старые `settings`-ключи (`pdf_source`, `group_name`,
   `daily_send_time`, `check_interval_minutes`, `timezone`,
   `weektype_url`) после успешной миграции не используются конфигом
   синка — читаются только из `groups`. Ключ `settings.last_sync_failed_at`
   становится per-group (переносится в саму таблицу `groups` как
   nullable колонка `last_sync_failed_at`, либо в отдельную таблицу —
   решается на этапе реализации, не меняет дизайн).

У единственной существующей группы (боевой `Б-Мв-101`) сейчас нет
сохранённого `source_page_url` — он никогда не запрашивался у админа.
Решение: новая переменная окружения `LEGACY_GROUP_SOURCE_PAGE_URL`
(обязательная только если на момент старта `settings.group_name`
непуста, т.е. есть что мигрировать); миграция использует её значение как
`source_page_url` первой строки `groups`. Если переменная не задана в
этой ситуации — бот не стартует и логирует явную ошибку конфигурации
(не падает молча и не создаёт группу с заведомо нерабочим 404-реканектом).

## Обработка 404 и создание группы

### Разрешение ссылки по названию группы

Общая чистая функция `resolve_pdf_link(html: str, group_name: str) ->
str | None`:
- Парсит HTML, собирает все `<a>` с `href`, оканчивающимся на `.pdf`.
- Возвращает первую ссылку, чей **видимый текст или href** содержит
  `group_name` как подстроку (регистронезависимо) — одна ссылка может
  относиться к двум группам одновременно (как в исходном баге), поэтому
  сравнение именно на вхождение, не на точное совпадение.
- Возвращает `None`, если совпадений нет.

Тестируется синтетическими HTML-фикстурами, без сети — по аналогии с
тем, как `build_schedule` тестируется на синтетических `RawRow`.

### Создание новой группы (любой пользователь)

`ConversationHandler`, запускается кнопкой «Создать группу» в списке
групп (см. «Выбор группы»):

1. Бот запрашивает название группы.
2. Бот запрашивает `source_page_url`.
3. Бот скачивает `source_page_url`:
   - сетевая ошибка/HTTP-ошибка на этом шаге → ошибка
     `SOURCE_PAGE_UNREACHABLE`, просит повторить ссылку.
   - скачалось → `resolve_pdf_link(html, group_name)`; `None` → ошибка
     `GROUP_LINK_NOT_FOUND`, просит проверить название/ссылку.
4. Найденную ссылку на PDF бот пробует реально скачать (не только
   проверить резолв) — чтобы не создать группу с мёртвой ссылкой.
   Ошибка на этом шаге → тоже `GROUP_LINK_NOT_FOUND` (с точки зрения
   пользователя разницы нет: расписание этой группы недоступно).
5. Успех → создаётся строка `groups` (дефолтные `send_time`/
   `check_interval_minutes`/`timezone`), автор закрепляется за ней
   (`members`, `subscribed=true`).

### 404-реканект при фоновой сверке (сам баг)

В `sync.py`: если скачивание текущего `groups.pdf_source_url` падает с
HTTP 404 (или в целом с ошибкой скачивания, не парсинга), перед тем как
считать попытку проваленной:

1. Скачать `groups.source_page_url` этой группы.
2. `resolve_pdf_link(html, groups.name)`.
3. Если найдена новая ссылка — обновить `groups.pdf_source_url`,
   повторить скачивание+парсинг с новой ссылкой как обычную попытку (в
   рамках существующего `MAX_SYNC_ATTEMPTS`, не бесконечный цикл).
4. Если `source_page_url` недоступен или совпадений нет — это финальная
   ошибка синка этой группы, как и раньше.

Текст ошибки (`SOURCE_PAGE_UNREACHABLE` / `GROUP_LINK_NOT_FOUND`) —
общий модуль форматирования, используемый и при создании группы, и в
уведомлении админу о сбое синка (единый источник, чтобы не разойтись).

## Выбор группы и подписка (`/start`)

- `/start` без закреплённой группы (`members` не содержит chat_id) →
  инлайн-список групп, сортировка по алфавиту, 8 на страницу. Переиспользуется
  паттерн `day:<...>`-callback из day-picker (`bot.py`): callback_data
  `grp:select:<id>` для выбора, `grp:page:<n>` для навигации,
  переиспользуется приём разбивки кнопок по рядам. Кнопка «Создать
  группу» (`grp:create`) — последней строкой всегда, на любой странице.
- Выбор группы → `members` upsert (`group_id`, `subscribed=true`,
  `telegram_username`/`display_name` из `update.effective_user`).
- `/start` при уже закреплённой группе → не переспрашивает, показывает
  текущий статус. Это заодно устраняет текущий баг с заморозкой
  `bot_data["group_name"]`: группа для `/start`/`/schedule`
  всегда читается из `members` по `chat_id` в момент запроса, а не из
  `bot_data`-снэпшота на старте процесса.
- `/unsubscribe` — `subscribed=false`, группа остаётся закреплённой,
  `/schedule` продолжает работать руками.
- `/subscribe` — возвращает `subscribed=true` без повторного выбора
  группы.
- Смена уже закреплённой группы на другую — не входит в этот под-проект
  (требует аппрува старосты/админа целевой группы — механизм аппрува
  появляется в под-проекте 2 вместе с ролью старосты).
- Любой хендлер, получающий `update.effective_user`, опортунистически
  обновляет `telegram_username`/`display_name` в `members` (самовосстановление
  профиля, см. «Модель данных»).

## Планировщик (per-group)

- При старте — для каждой строки `groups` регистрируется своя пара job'ов
  (hourly check + daily send) с cron-триггером по `send_time`/
  `check_interval_minutes`/`timezone` этой группы.
- `reschedule_daily_job`/`reschedule_hourly_job` принимают `group_id`,
  пересоздают job только этой группы.
- `sync_fn`, `active_schedule_getter`, `active_pdf_path_getter` в
  `bot_data` параметризуются `group_id` вместо замыкания на глобальные
  настройки.
- Админ-команды `/set_pdf_source`, `/set_send_time`, `/set_check_interval`
  получают `group_id` первым аргументом (или выбор группы через тот же
  инлайн-пикер с пагинацией, что в «Выбор группы») — старое поведение
  «без аргумента = единственная глобальная группа» убирается.
- Уведомление админу о финальном сбое синка включает название группы.
- `/alert <текст>` — остаётся **глобальной** рассылкой (не per-group):
  это канал админа для объявлений про сам бот (например, о релизах/
  технических работах), адресован всем пользователям бота сразу, а не
  подписчикам одной группы. Реализация меняется только внутри —
  вместо `storage.list_subscribers(conn, group_name)` используется
  новая `storage.list_all_member_chat_ids(conn)` (все `chat_id` из
  `members`, по всем группам, без дублей за счёт `chat_id` как PK).
- Каждый per-subscriber send-цикл (hourly notify, daily send, `/alert`)
  продолжает изолировать отказы отдельных chat_id — существующий
  паттерн try/except на каждую отправку не меняется.

## Тестирование

- `resolve_pdf_link` — синтетические HTML-фикстуры (без сети): ссылка на
  одну группу, ссылка на две группы через один href/текст, страница без
  совпадений, повторяющиеся совпадения (берём первое).
- Миграция `settings`→`groups`, `subscribers`→`members` + backfill
  username через `get_chat` — мок-`Bot`, по образцу существующих тестов
  `test_main_wiring.py`.
- Per-group scheduler jobs — тесты обязаны выключать/дожидаться
  завершения APScheduler-инстансов (см. предупреждение в CLAUDE.md про
  утечки scheduler'а в существующих тестах `test_scheduler.py` —
  новые тесты не должны повторять эту проблему).
- 404-реканект в `sync.py` — тест на моках HTTP-клиента: первая попытка
  404 → подстановка новой ссылки → успешный повторный синк; и негативный
  кейс (страница-источник тоже недоступна → финальная ошибка).
- `ConversationHandler` создания группы — тест полного диалога (имя →
  ссылка → успех) и каждой ветки ошибки (`SOURCE_PAGE_UNREACHABLE`,
  `GROUP_LINK_NOT_FOUND`).

## Вне охвата этого под-проекта

- Роль старосты, голосования за назначение/смену, смена уже закреплённой
  группы с аппрувом (под-проект 2).
- Сохранение списка одногруппников как пользовательской фичи (`members`
  уже хранит нужные поля, но команда просмотра списка — под-проект 3).
- Исключение из группы, закрытые/открытые группы, `/notify` (под-проект 4).
- Редизайн UI в инлайн-меню (под-проект 5) — команды в этом под-проекте
  остаются текстовыми (`/start`, `/schedule`, `/subscribe`,
  `/unsubscribe`, `/set_pdf_source`, ...).
