# Телеграм-бот расписания занятий — дизайн

Дата: 2026-09-16

## Назначение

Telegram-бот, который:

1. Ежедневно утром присылает подписчикам расписание занятий на сегодня.
2. Раз в час проверяет, не изменилось ли расписание в исходном PDF, и если да — сразу применяет изменения и оповещает подписчиков.
3. По команде `/schedule` показывает расписание на выбранный день недели по кнопкам.
4. Учитывает тип учебной недели (Верхняя/Нижняя), который определяет, какой из двух вариантов пары показывать, если пара в этот день/время раздваивается.

Область охвата сейчас — одна группа (`Б-Мв-101` по умолчанию, настраивается). Архитектура закладывает возможность в будущем расширить до множества групп/пользователей без изменения схемы БД, но UI/логика мульти-группы не реализуются в этой итерации (YAGNI).

## Источники данных

### 1. PDF с расписанием

- Настраиваемый источник `pdf_source`: либо HTTP(S) URL, либо локальный путь к файлу на диске (определяется по наличию схемы `http://`/`https://`). Локальный путь нужен для удобной ручной проверки — можно подкладывать любые PDF в проект и переключать бота на них без сети.
- Текущий боевой URL: `https://www.vavilovsar.ru/files/pages/41427/1789471639_1%20курс%20БЭ,%20БМ%20оз.pdf` (пример, будет когда-то замён институтом на новый семестр — оттого и настраиваемость).
- Формат: одна таблица на странице. Строки — дни недели (день "растянут" по вертикали через объединение первой колонки) и временные слоты; часть слотов внутри дня разбита на дополнительную безвременную строку — это означает, что в это время идут два разных предмета в зависимости от типа недели.
- Колонки групп определяются по тексту заголовка (например, "Б-Мв-101"), а не по индексу — так парсер переживёт смену порядка колонок между семестрами.

### 2. Тип недели

- Источник: `https://www.vavilovsar.ru/ucheba/raspisanie-zanyatii` — в HTML прямо зашит `<script>`, вычисляющий тип недели на клиенте:

```js
const baseDate = new Date(year, 0, 5); // опорная дата
const weekIndex = Math.floor((today - baseDate) / 86400000 / 7);
const weekType = weekIndex % 2 === 0 ? 'Верхняя' : 'Нижняя';
```

- Бот не скрапит отрендеренную страницу (значение генерируется в браузере), а регуляркой достаёт из исходного текста скрипта: (а) опорную дату (`new Date(year, 0, 5)` → месяц/день), (б) какой ветке чётности соответствует "Верхняя". По этим данным тип недели для любой даты считается локально, без сети, при каждом обращении.
- Раз в неделю (и при старте) бот перечитывает страницу, чтобы подхватить возможное изменение опорной даты/формулы. Если ожидаемый паттерн в скрипте не найден — админу отправляется предупреждение, а бот продолжает работать на последних сохранённых константах (не падает).

## Разбор PDF: детали алгоритма

1. Скачать/прочитать PDF, получить единственную таблицу через `pdfplumber` (`page.find_tables()[0]`), включая текст ячеек (`table.extract()`) и геометрию ячеек (`table.rows[i].cells`, bbox).
2. Найти колонку целевой группы по тексту в строке заголовка.
3. Пройти по строкам сверху вниз, "протягивая" день недели и время вниз через пустые (объединённые) ячейки первых двух колонок.
4. Для каждой строки внутри временного слота:
   - Если ячейка целевой группы содержит текст — это либо единственный вариант пары (действует в любую неделю), либо, если внутри слота больше одной строки, один из двух вариантов.
   - Если внутри временного слота несколько строк (безвременных продолжений): **первая (верхняя) строка = пара для Верхней недели, вторая (нижняя) = пара для Нижней недели** (подтверждено пользователем как стандартная конвенция; в PDF это нигде явно не подписано).
   - **Общая пара для нескольких групп**: определяется геометрически — если ячейка группы 1 в этой строке имеет `x1` (правая граница), доходящий до правого края всей таблицы (перекрывает область целевой группы), а не только до границы своей колонки, то это объединённая ячейка, и её текст относится и к целевой группе тоже. Если `x1` заканчивается на границе группы 1, а ячейка целевой группы в этой под-строке пуста — значит у целевой группы в этот слот просто нет занятия (не общая пара).
5. Помимо текста, для каждого дня запоминается вертикальный диапазон (`y0`, `y1`) всех его строк в таблице — понадобится для вырезания картинки (см. раздел «Скриншот дня»).
6. Результат — структура вида:

```json
{
  "monday": {
    "bbox": {"y0": 235.4, "y1": 253.7},
    "lessons": [
      {"time": "8.30-10.00", "upper": "Предмет A / преп. / ауд.", "lower": null},
      {"time": "13.40-15.10", "upper": "Общая пара X", "lower": "Общая пара X"}
    ]
  },
  "...": {}
}
```

(`upper`/`lower` одинаковы для несплитованных и общих пар.)

7. Парсинг — best-effort. Он не обязан быть идеальным с первого раза: любые аномалии видны в логах и в diff-уведомлении админу; при необходимости эвристики донастраиваются по факту. Формальная защита от полного слома — юнит-тесты на сохранённой PDF-фикстюре плюс на паре синтетических edge-кейсов (несимметричное разбиение колонок, общая пара).

## Хранение (SQLite)

- `subscribers(chat_id INTEGER PRIMARY KEY, group_name TEXT NOT NULL, joined_at TEXT)` — `group_name` заполняется из текущей настройки `settings.group_name` на момент подписки; сейчас у всех одно и то же значение, но колонка уже поддерживает будущее разделение по группам.
- `schedule_versions(id INTEGER PRIMARY KEY, group_name TEXT NOT NULL, payload_json TEXT NOT NULL, pdf_cache_path TEXT NOT NULL, parsed_at TEXT NOT NULL, status TEXT NOT NULL)` — `status` = `active` (одна активная версия на группу) или `superseded` (история). Diff всегда считается против текущей `active` версии для той же `group_name`. `pdf_cache_path` — путь к копии PDF-файла, из которого была получена эта версия (см. «Скриншот дня»).
- `settings(key TEXT PRIMARY KEY, value TEXT)` — редактируется админскими командами в рантайме, без передеплоя. Заполняется дефолтами из `.env`/переменных окружения при первом запуске, если ключа ещё нет в таблице. Ключи:
  - `pdf_source` — URL или локальный путь.
  - `group_name` — целевая группа (сейчас одна).
  - `weektype_url`.
  - `daily_send_time` — `HH:MM`, таймзона ниже.
  - `check_interval_minutes` — интервал почасовой(настраиваемой) проверки, по умолчанию `60`.
  - `timezone` — по умолчанию `Europe/Moscow`.

Diff между двумя версиями считается по разобранной структуре (день/время/upper/lower), а не по сырому тексту PDF — так вёрсточный шум не порождает ложных уведомлений об изменении.

## Планировщик (APScheduler)

Общая функция `check_and_apply_diff(group_name)`:
1. Скачать/прочитать PDF по `settings.pdf_source`, распарсить.
2. Сравнить с активной версией в БД для `group_name`.
3. Если отличий нет — вернуть "без изменений".
4. Если есть — сохранить новую версию как `active` (старую пометить `superseded`), разослать подписчикам этой группы сообщение "Расписание изменилось" с кратким описанием diff, вернуть "применено".

Джобы:
- **Почасовой** (интервал = `settings.check_interval_minutes`, перечитывается при изменении настройки) — вызывает `check_and_apply_diff` и ничего не делает, если изменений нет.
- **Ежедневный** (время = `settings.daily_send_time`, таймзона = `settings.timezone`) — вызывает `check_and_apply_diff`, затем в любом случае шлёт подписчикам расписание на сегодня из (уже актуальной) активной версии, с учётом типа недели этого дня.
- **Еженедельный** (например, понедельник 06:00) — обновляет закэшированные константы типа недели с `weektype_url`.

Изменение `daily_send_time`/`check_interval_minutes` через админ-команды сразу переустанавливает соответствующий job в APScheduler (без рестарта процесса).

## Скриншот дня

Вместе с текстом расписания на день (и в ежедневном сообщении, и в `/schedule`) присылается картинка — вырезанная из PDF полоса строк этого дня.

- При создании новой `active`-версии в `check_and_apply_diff` копия скачанного/прочитанного PDF-файла сохраняется на диск (`data/pdf_cache/<group_name>/<version_id>.pdf`), путь пишется в `schedule_versions.pdf_cache_path`. Старые файлы прошлых версий можно не хранить долго (удалять при появлении новой `active`-версии той же группы), поскольку картинка нужна только для текущего расписания.
- Рендер — через `PyMuPDF` (`fitz`), без внешних системных зависимостей (в отличие от `pdf2image`/`poppler`), что упрощает Docker-образ:
  1. Открыть закэшированный PDF, получить страницу.
  2. Отрендерить в pixmap с увеличением (например, `zoom ≈ 2.5–3`, чтобы текст оставался читаемым в Telegram).
  3. Обрезать по ширине — вся таблица; по высоте — сохранённый `bbox.y0`/`bbox.y1` этого дня (с небольшим отступом сверху/снизу для читаемости), пересчитанные на масштаб рендера.
  4. Отдать PNG-байты в `bot.send_photo` вместе с текстом подписи (caption) — сам текст расписания дублируется текстом, картинка — как наглядное дополнение из оригинала.
- Если файл `pdf_cache_path` для активной версии почему-то отсутствует на диске (например, том случайно почистили) — бот отправляет только текст, без картинки, и пишет предупреждение в лог (не роняет отправку расписания).

## Телеграм-бот (python-telegram-bot, long polling)

Пользовательские команды:
- `/start` — подписка (добавление в `subscribers` с текущим `group_name`).
- `/stop` — отписка.
- `/schedule` — инлайн-кнопки с днями недели (Пн–Вс); по нажатию — расписание на этот день из активной версии, с учётом типа недели на ближайшую дату этого дня недели.

Админские команды (доступны только `chat_id == ADMIN_CHAT_ID`):
- `/set_pdf_source <url_или_путь>`
- `/set_group <название>`
- `/set_send_time <HH:MM>`
- `/set_check_interval <минуты>`
- `/refresh` (и/или инлайн-кнопка "Обновить сейчас") — немедленно вызывает `check_and_apply_diff`, отвечает админу результатом.
- `/alert <текст>` — немедленно рассылает произвольное текстовое сообщение всем подписчикам (например, если админ вручную заметил ошибку раньше автопроверки).

## Конфигурация и секреты

`.env` (только для первого запуска/секретов, не редактируется в рантайме):
- `TELEGRAM_BOT_TOKEN`
- `ADMIN_CHAT_ID`
- `DB_PATH` (по умолчанию `./data/schedule.db`)
- Дефолтные значения для `settings`, если таблица пуста при первом старте (`PDF_SOURCE`, `GROUP_NAME`, `WEEKTYPE_URL`, `DAILY_SEND_TIME`, `CHECK_INTERVAL_MINUTES`, `TIMEZONE`).

## Тестирование

- Юнит-тесты `pdf_parser`: на сохранённой в репозитории PDF-фикстюре (текущий файл расписания) + синтетические edge-кейсы (несимметричное разбиение колонок между группами, общая пара, слот без разбиения).
- Юнит-тесты `weektype`: на захардкоженном HTML-фикстюре с `<script>`-блоком; проверка вычисления по нескольким датам.
- Юнит-тесты diff-логики: разные версии структуры → ожидаемый список изменений.
- Локальная сквозная проверка: указать `pdf_source` на локальный файл, вызвать `/refresh` в тестовом чате, проверить `/schedule`.

## Деплой

- `Dockerfile` + `docker-compose.yml`.
- `data/` — volume для файла SQLite (переживает пересборку контейнера).
- Секреты — через `.env`, не коммитятся.

## Технологии

- Python 3.12+
- `python-telegram-bot` (async, polling)
- `pdfplumber` — разбор PDF
- `PyMuPDF` (`fitz`) — рендер скриншота дня из PDF
- `APScheduler` — джобы
- `sqlite3` (stdlib) — без ORM, простые запросы
- `pytest` — тесты
