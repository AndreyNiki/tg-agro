# Инлайн-меню — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a role-aware `/menu` navigation layer over every existing command from sub-projects 1-4, without duplicating any business logic.

**Architecture:** A small `telegram_utils.reply(update, text, **kwargs)` helper lets zero-argument command handlers (originally written assuming `update.message`) work unchanged when invoked from a callback-query context (`update.callback_query.message`) — this is what lets the menu call `schedule_command(update, context)` directly instead of reimplementing it. Text-argument admin/starosta commands (`set_pdf_source`, `set_send_time`, `set_check_interval`, `set_starosta`, `remove_starosta`, `notify`, `alert`) get their validation+write+reply logic extracted into `_apply_*` core functions, called by both the existing slash-command handler and a generic `pending_menu_action` follow-up `MessageHandler` the menu installs. `schedule_bot/menu.py` owns the root keyboard, section builders, and navigation callbacks.

**Tech Stack:** Same as prior sub-projects.

**Spec:** `docs/superpowers/specs/2026-10-08-menu-ui-design.md`

**Depends on:** sub-projects 1-4 in full (every command and module they introduced).

## Global Constraints

- No new business logic — every menu leaf either calls an existing handler unchanged (via `telegram_utils.reply`) or calls a newly-extracted `_apply_*` core function that the matching slash command also calls.
- `pending_menu_action` is consumed exactly once per attempt: the generic follow-up `MessageHandler` clears it from `context.user_data` whether the core function succeeds or reports a validation error, so a stale pending action never leaks into an unrelated later message.
- The generic follow-up `MessageHandler` must be registered **after** every `ConversationHandler` in `main.py`'s handler list, so it never intercepts a `ConversationHandler`'s own text steps (e.g. group creation).
- Role visibility (which root buttons appear) is computed fresh on every `/menu` call and every "⬅ Назад" to root — never cached in `user_data`.

## Review Focus

- A plain member (not starosta, not admin) must never see the "👑 Староста" section's privilege buttons, even transiently, if they happen to tap into it right after being removed as starosta.
- `pending_menu_action` must not persist across unrelated messages — typing something in chat with no pending action must not be swallowed by the generic follow-up handler.
- An admin text-arg flow (e.g. "🔧 Настройки группы" → "Источник PDF") must apply to the **group picked in that flow**, not some other group left over from a previous menu session, even if the admin starts two flows back-to-back without finishing the first.
- The "◀️ Назад" button must return to the immediately preceding screen, not always the root, when a user is two levels deep (e.g. admin → group settings submenu).
- Calling a zero-arg leaf (e.g. `/classmates`-via-menu) through `telegram_utils.reply` must produce the exact same text a direct `/classmates` call would, including the exclude buttons for a starosta caller.

```python
async def reply(update, text, **kwargs) -> None:
    """Replies through whichever of update.message/update.callback_query.message
    is actually populated — lets a handler written for a plain /command
    invocation also work unchanged when the menu calls it directly with
    a callback-query Update."""
    if update.message is not None:
        await update.message.reply_text(text, **kwargs)
    else:
        await update.callback_query.message.reply_text(text, **kwargs)
```

```python
import logging

from schedule_bot import storage
from schedule_bot.elections import format_candidate_label
from schedule_bot.telegram_utils import send_with_retry

logger = logging.getLogger(__name__)


def format_report_message(reporter, group, chat_id: int, text: str) -> str:
    label = format_candidate_label(reporter) if reporter is not None else "Неизвестный"
    group_name = group.name if group is not None else "—"
    return f"🆘 Жалоба от {label} (chat_id={chat_id}, группа: {group_name}):\n\n{text}"


async def _apply_report(conn, bot_client, admin_chat_id: int, chat_id: int, text: str) -> str:
    reporter = storage.get_member(conn, chat_id)
    group = storage.get_group(conn, reporter.group_id) if reporter is not None else None
    message = format_report_message(reporter, group, chat_id, text)
    try:
        await send_with_retry(lambda: bot_client.send_message(chat_id=admin_chat_id, text=message))
    except Exception as error:
        logger.warning("report: failed to forward to admin: %s", error)
    return "Сообщение отправлено администратору."


async def report_command(update, context) -> None:
    if not context.args:
        await update.message.reply_text("Использование: /report <текст>")
        return
    text = " ".join(context.args)
    conn = context.bot_data["conn"]
    result = await _apply_report(
        conn, context.bot, context.bot_data["admin_chat_id"], update.effective_chat.id, text
    )
    await update.message.reply_text(result)
```
